# 2026-09-21 — Famorian, and the syntax-check drift

> **2026-09-22: every item below was re-checked against the code and the mechanical ones built.**
> Current status of each is in `2026-09-22-sonnet-backlog.md`, which wins where this note disagrees.

Third pass of the day, and it finishes the race layer: every race in his `specieslist` now exists as
a document. See `DECISIONS.md` 2026-09-21 (the last two entries) and `UPSTREAM-ISSUES.md` item 49.

**Already decided, do not re-litigate:**
- Evokes are **an array on the actor** (`physical.famorian.evokes`, his own checkbox keys — NOT
  `identity.famorian`, which this note itself said on 2026-09-21 and which was wrong: `identity`
  has no `famorian` field, so every read of it silently returned nothing, and the evokes were never
  applied at all until this was found and fixed 2026-09-22. See DECISIONS.md that date.), not Items
  and not Active Effects. The user's call.
- The breed is **rolled**, with a world setting to choose instead — the handedness shape.
- Only **fifteen** evokes change a number; they are in `module/famorian-rules.mjs` with his line
  cited on each. The other ~105 are listed and not applied, as racial abilities already are.
- The base race is the **else** branch of every evoke test. A Famorian with no evokes has −10%
  disease resistance and a 1d4 Endurance roll.
- Evokes apply in **his** order, not the order they were ticked. Wings beat legs beat insect legs
  beat fins; the last speed evoke wins.
- Over-budget and a missing animal type are **reported, never refused**.

## Mechanical follow-through

1. **DONE 2026-09-22.** The generator now has a Famorian step, folded into the Race step rather
   than a page of its own: a breed roll or dropdown (`famorianBreedSelectable`, registered beside
   handedness), an animal type field, and an evoke picker (all ~120, alphabetical, the numeric
   fifteen in bold) showing the budget used against allowed. Verified as a full round trip --
   generator choices through `assembleCharacter` into a real `ImagineCharacterData` rebuilding the
   identical race -- and the real Handlebars template was rendered against real content, not just
   the JS view object. **Finding it revealed the `identity.famorian` bug above**, which this pass
   fixed first. See `DECISIONS.md` 2026-09-22, "A Famorian can be made in the character
   generator...". Bundled in: the Formless host picker's own missing `formlessIssue` display (a gap
   from 2026-09-21, found while extending the same template region), and a new automated-test
   section for `module/chargen-view.mjs`, which had none before this pass.

2. **The character sheet does not show the evokes.** `describeEvokes` already returns label, detail
   and whether it is numeric; the Description tab's Race panel should list them in the same chip
   markup the racial abilities use, with the breed and the budget beside them. Files:
   `templates/actor/tab-description.hbs`. Done when a Famorian with wings and night vision shows
   both, and the budget line reads "3 of 4".

3. **`famorian` is not editable on the race item sheet** — the breed table and the 120-entry
   catalogue are read-only data a Game Master might want to extend. Lower priority than the other
   list fields (item 2 of `2026-09-21-formless-and-resistances.md`) because nobody hand-authors a
   second Famorian, but it is the same gap.

4. **`docs/DATA-MODEL.md`** gains `famorian` on the race item (`isFamorian`, `breeds`, `evokes`) and
   `identity.famorian` on the character (`breed`, `animalType`, `evokesAllowed`, `evokes`, the three
   bonuses). Add rows, reword nothing.

5. **Localise**, if the other tabs do: the evoke budget issue and the animal-type issue in
   `_getRaceIssues`, and whatever items 1 and 2 add.

6. **`describeEvokes` is exported by `module/famorian-rules.mjs` and nothing calls it yet.** It is
   what item 2 needs: it returns label, detail and whether the evoke is numeric. It is tested, so
   it will not have drifted when you come to use it. (The unused import of it was removed from
   `actor-character.mjs` rather than shipped half-wired.)
