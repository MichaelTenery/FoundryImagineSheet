the parallel branch `wip/magic-m1` had and main lacked. The decisions are in `docs/DECISIONS.md`,
"Reconciling the two magic branches (2026-09-24)". Already decided and **not to be re-litigated**:

## The mechanical follow-through

1. **The previews.** `tools/magic-preview.html` renders the Magic & Lore tab and three cast cards.
   Give its Mage one spell with `days: 0` (the "forgotten" mark and the disabled Cast show), and add a
   fourth card from `R.performSpellCast` with a mishap roll of 87 (Aura Loss), so the Apply button is
   seen. `tools/item-preview.html`'s spell: give it `days: 12`. Done when both render with no console
   errors over HTTP.

2. **The failure and mishap d100s as Foundry rolls on the card.** `castSpell` draws every die through
   `getDieRoll` (casting-helpers.mjs, `CONFIG.Dice.randomUniform`), so the card has no roll tooltip and
   Dice So Nice shows nothing. Evaluate the cast's d100s as `new Roll("1d100")` before
   `performSpellCast`, feed their totals in through a small queue ahead of `getDieRoll`, and pass
   `rolls: [...]` to the card. The rules stay Foundry-free. Done when a mishap card shows its d100s as
   rolls and `node tools/run-tests.mjs casting` still passes. (Carried over from the parallel branch's
   note; it applies to main's cast the same way.)

3. **The prayer's words under test.** `prayForInvocation` (casting-actions.mjs) keeps his prayer
   lines in the action. Move them into a `describePrayer(tmpresult, tmpwords)` in casting-rules.mjs,
   as `describeRememorize` is, and check each outcome (alreadyKnown, notMemorized, wrongAlignment,
   overPietyControl, denial, noMemory, noDevotion, grandmaster, fumble, critical, failure, success)
   against his handlePrayForInvocation (152516) and handleReprayForInvocation (153326). Done when each
   has a check in `tools/casting-test.html`.

4. **Rebuild the code graph** once this is merged (`graphify update ./module --no-cluster`, then
   `./tools`, then `merge-graphs`, as CLAUDE.md gives it).

5. **The content packs' build drift.** Running `python tools/extract/build_documents.py --write` in a
   checkout without the local-only book text (`docs/reference/*-fulltext.txt`, which a worktree does
   not have) changes `isRestricted` on many skills in `skills.json` from true to false: the build
   looks for a "Restricted:" heading in the book (`lookup_restricted`) and writes false when the book
   is missing. This pass kept only the consumables and lore packs' subsystem changes and restored
   `skills.json`. Make the build stop with a message when the book text it reads is absent, rather
   than writing a different pack. Done when a run without the books leaves `skills.json` unchanged or
   stops and says why.
