The module is in a private repo, `C:\Users\samwy\imagine-hexland` (local git, **no remote — his ruling,
2026-10-21**). Never copy its content into this repository; this note and the board rows say only where

Already decided. See DECISIONS 2026-10-21 (both entries); don't re-open:

- A separate module, compiled LevelDB packs at build time (not this system's runtime importer).
- Rollable tables become RollTables and sit embedded in the journal page that prints them; lookup charts
  stay HTML tables in the text.
- Roll with Modifier clamps *inside the formula*, because Foundry's own draw re-rolls a total that misses
  every row and so throws his modifiers away.
- Scan errors are fixed silently; the author's own slips are kept as printed and listed for him.
- `python tools/build_module.py --install DIR` needs a Foundry user-data folder named explicitly. It once
  defaulted to the Foundry a game is run from; it must never guess that again.

1. **Phase 2-4 transcription, section by section.** Same pipeline as Phase 1: the page images and text are
   rendered with PyMuPDF (`pymupdf`, `get_pixmap(dpi=130)`) into a scratch folder; an inventory pass lists every
   table and heading per page; one agent per section writes `src/journal/<part>/NN-slug.html` and
   `src/tables/<part>/NN-slug.json` to the spec; two independent auditors (a tables lens and a text lens)
   compare each against the page images; a fix pass applies what the images confirm; a second audit runs only
   where the first changed something. Add each section to the part's `pages.json`. Done when
   `python tools/build_module.py` prints "no problems", the 42-document schema check passes, and every section has
   been audited by both lenses (an auditor that died is **not** a clean audit — the workflow script reports
   these as `unaudited`; re-run until none). Phase 1 took four resumes because of usage limits; budget for it.
2. **Fill the book page numbers** into `pages.json` (each journal page has `"page": null`); the tables
   already carry theirs.
3. **Live check in V14.** Phase 1 was loaded and rolled only in a scratch Foundry **V13** build 347 (the
   copy installed here); the module declares V14. In a V14 world with the real `imagine-rpg` system: the two
   compendia appear under one folder; Weather's sheet shows **Roll with Modifier** beside Draw Result; "+2 +2" is
   read as +4; the Reaction Handler journal renders and its embed's roll button works. Done when each is ticked
   here. The scratch server is `foundry-v13-test` in this repo's (git-ignored) `.claude/launch.json`; it needs
   its module.json's `compatibility.minimum` lowered to 13 in the *scratch copy only*.
4. **The embedded roll button has no modifier.** A table embedded in a journal page rolls with Foundry's own
   button, unmodified; Roll with Modifier exists only on the table's own sheet. The Reaction Table and Weather
   are the two that need it most. Add a Roll with Modifier control to the embed (`renderJournalEntryPageTextSheet`
   or an enricher; the embed template is `templates/tables/embed.hbs`). Small, but it touches rendering, so check
   it in a running Foundry.
5. **Negative ranges read badly in the embed** ("-50—-41", core's `lo—hi` join). Cosmetic; only worth doing if
   the embed work in item 4 makes it free.
6. **When he rules on `docs/ODDITIES.md`** (the module repo): apply each ruling to `src/`, rebuild. The
   places the module departs from print are listed at the top of that file, with what is printed and what the
   module does instead; read them there (they are his book's content, so they are not repeated here). Three
   tables could not be stored as printed because the build refuses overlapping ranges or dice that miss a
   row; two print gaps, where a roll lands on nothing and Foundry re-rolls. Not mechanical: *which* reading
   is his.
